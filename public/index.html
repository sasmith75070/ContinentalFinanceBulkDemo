Use Case 1

Fire and forget · Compliance Toolkit handles the send window

Continental Finance sends 3.5M payment reminders a month. Instead of computing timezone-safe send windows in their scheduler, they enable Twilio's Compliance Toolkit — every message passes through per-recipient TCPA quiet-hours enforcement (plus state-specific overlays for AL/FL/LA/MD/MS/OK/TN/WA/CT/NV/TX). Continental Finance fires whenever; Twilio delivers within safe hours per cardholder, automatically.

Twilio Products used
  • Programmable Messaging · Create Message · POST /2010-04-01/Accounts/{Sid}/Messages.json
    Actively invoked by the Send button. Server calls client.messages.create() with the Messaging Service SID, the recipient's number, the personalized body, and messageIntent. Returns a MessageSid and an initial status.
    Docs ↗
  • Compliance Toolkit · Console-enabled · per-recipient Quiet Hours enforcement
    Twilio evaluates every outbound US SMS against the recipient's local TCPA quiet hours (9pm–8am) plus stricter state windows. Non-essential messages sent inside quiet hours are auto-rescheduled for later delivery (status becomes scheduled with a ScheduledAt). Essential messages tagged via messageIntent — otp, notifications, fraud, security, customercare, delivery — bypass Quiet Hours entirely.
    Docs ↗
  • Fetch Message · GET /Messages/{Sid}.json
    Polled every 750ms to update the status card. If CT rescheduled the message, status shows scheduled plus a ScheduledAt; otherwise queued → sending → sent → delivered.
    Docs ↗
  • Messaging Service
    Owns the sender pool (Continental Finance's short codes in production) plus Advanced Opt-Out. Referenced on every send.
    Docs ↗

What this proves

  • No timezone math in Continental Finance's scheduler. Fire whenever. CT infers each recipient's local zone from area code (or ZIP if provided) and enforces TCPA 9pm–8am plus state-specific overlays automatically.
  • Auto-reschedule out of Quiet Hours. Non-essential message sent inside quiet hours → CT reschedules for the next allowed window. Status flips to scheduled with a ScheduledAt. Continental Finance sees the outcome via GET /Messages/{Sid} or status callbacks.
  • Essential messages bypass Quiet Hours. Tag with messageIntent: 'notifications' (or otp, fraud, customercare, delivery, security) and CT lets them through immediately. Continental Finance's counsel decides what classifies as essential for their program.
  • Per-message MessageSid. Every send is individually addressable, auditable, and (as Use Case 2 shows) cancellable via Update Message.
  • Personalization is server-rendered. Continental Finance's application builds the body per cardholder before the API call. Full flexibility, no template language limits.
  • Scheduling still available if needed. If Continental Finance wants explicit control over a specific send time — say, a coordinated statement blast at 10am local — scheduleType=fixed + sendAt is available on the same endpoint. Talk-track only in this demo; not the primary pitch.

Use Case 2

Pull back a scheduled SMS the instant a payment posts

Continental Finance schedules Jane's payment reminder for 10am tomorrow. Between now and then, Jane pays. Continental Finance's payment webhook fires and Twilio's Update Message API flips that specific message to canceled. Jane never gets the "past-due" text she doesn't need.

Twilio Products used
  • Programmable Messaging · Create Message · POST /2010-04-01/Accounts/{Sid}/Messages.json
    Actively invoked by the Schedule button with scheduleType=fixed, sendAt=+20min, and the Messaging Service SID. Twilio returns a MessageSid and status=scheduled.
    Docs ↗
  • Message Scheduling · scheduleType=fixed + sendAt
    Requires a Messaging Service. Fires at the exact sendAt. Cancellable while still in scheduled state.
    Docs ↗
  • Programmable Messaging · Update Message · POST /Messages/{Sid}.json with Status=canceled
    Actively invoked by the Payment-posted button. Flips the scheduled message's status; Twilio drops it before it reaches the carrier.
    Docs ↗
  • Messaging Service
    Required for both scheduling and cancellation. Owns the sender pool the SMS fires from.
    Docs ↗
