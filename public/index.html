Use Case 1

Send a payment reminder

Continental Finance's core outbound program — payment reminders and past-due messaging. Whether the reminder is proactive (statement due in N days) or reactive (payment past-due), the mechanic is the same: personalized SMS to 3.5M cardholders per month with per-recipient delivery status and native scheduling, from a single API call.

What this proves

  • One API call, one MessageSid. POST /Messages.json creates a single message. At Continental Finance's 3.5M/mo (~4/sec average, higher at peak) this becomes a fan-out — one call per cardholder — well within a short code's 100 MPS throughput.
  • Personalization is server-rendered. Continental Finance's application builds the body per cardholder before the API call. Full flexibility, no template language limits.
  • Per-message status. GET /Messages/{Sid}.json returns the current lifecycle state. Status callbacks also stream every transition to the inbound webhook for BI and audit.
  • Native scheduling. scheduleType=fixed + sendAt, between 15 minutes and 7 days out. Continental Finance computes per-cardholder timezone at schedule time.

Use Case 2

Pull back a scheduled SMS the instant a payment posts

Continental Finance schedules Jane's payment reminder for 10am tomorrow. Between now and then, Jane pays. Continental Finance's payment webhook fires and Twilio's Update Message API flips that specific message to canceled. Jane never gets the "past-due" text she doesn't need.

Twilio Products used
  • Programmable Messaging · Create Message · POST /2010-04-01/Accounts/{Sid}/Messages.json
    Actively invoked by the Schedule button with scheduleType=fixed, sendAt=+20min, and the Messaging Service SID. Twilio returns a MessageSid and status=scheduled.
    Docs ↗
  • Message Scheduling · scheduleType=fixed + sendAt
    Requires a Messaging Service. Fires at the exact sendAt. Cancellable while still in scheduled state.
    Docs ↗
  • Programmable Messaging · Update Message · POST /Messages/{Sid}.json with Status=canceled
    Actively invoked by the Payment-posted button. Flips the scheduled message's status; Twilio drops it before it reaches the carrier.
    Docs ↗
  • Messaging Service
    Required for both scheduling and cancellation. Owns the sender pool the SMS fires from.
    Docs ↗

    Every inbound message, captured and actionable

    Capture every cardholder response, handle STOP/START/HELP compliantly via Twilio-native automation (no code), route free-form text to a human review queue, and enforce app-side Do-Not-Contact suppression across every sender Continental Finance owns.

    Twilio Products used
    • Advanced Opt-Out · Messaging Service feature
      Actively demonstrated. Twilio auto-replies to STOP / START / HELP with custom Surge copy, updates its block list, and POSTs the event to our webhook with an OptOutType header for audit. No code.

    • Inbound Webhook · POST /webhooks/twilio/inbound
      Actively receives every inbound SMS — keyword-matched and free-form both. Free-form lands in the Ops Review Queue for a human.

    • Messaging Service
      Owns the Advanced Opt-Out configuration, the sender pool, and the inbound webhook URL. Console-managed.
