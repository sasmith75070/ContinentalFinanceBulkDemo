What this proves

  • One API call, thousands of sends. POST https://comms.twilio.com/v1/Messages with a to[] array of up to 10,000 recipients.
  • Personalization is native. Liquid variables ({{firstName}}, {{amountDue}}) resolve per-recipient with default filter fallbacks.
  • Operations resource returns per-recipient status. Delivered · Failed · Unaddressable counters advance in real time.
  • Send window (8am–9pm ET). Continental's own scheduler decides send time. Compliance Toolkit's per-message classification is Programmable Messaging only — we're intentionally not claiming it here.

    Scene D · talk-track

    Business-user self-service for campaign administration

    This scene is intentionally not interactive. It maps RFP use case 4 to Twilio Console self-service capabilities — honestly.

    Business users can self-serve for

    • DNC / suppression list management · Messaging > Advanced Opt-Out
    • Opt-out confirmation wording · custom Surge copy without redeploying code
    • Sender Pool / Messaging Service configuration · add/remove numbers, rules
    • Scheduling adjustments & pausing campaigns · Bulk scheduling up to 7 days out
    • Delivery monitoring, alerts, reports · Console + Insights + Event Streams

    Where we concede honestly

    Changing the SMS body copy itself still requires an application code change. Twilio does not ship a business-user editor for SMS body text.

    If Continental wants a business-user-facing content editor on top of Bulk Messaging, that's a scoped services engagement — separately quoted. We won't fake it in this demo.

    For everything except message body copy, Console + IAM roles cover it.
